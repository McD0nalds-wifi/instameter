# Выборочное чтение документации через doc-map

Доки в этом проекте читаются ВЫБОРОЧНО через индекс `docs/doc-map.json`, а не целиком.

## Когда применять — на каждом запросе, не только на первом

Скилл отрабатывает на КАЖДОМ запросе сессии и на каждом шаге рассуждения, где ты
собираешься читать/править код или отвечать на вопрос об устройстве кода — не только на
первом запросе. Новый запрос или новый виток рассуждения (перешёл к другому файлу кода или
к другой подтеме) = заново пройди селекцию ниже. Это не «сработало один раз и забыто».

## Сверка индекса — один раз за сессию (и после правок доков)

1. Запусти `yarn doc-map`. Скрипт пересобирает механические поля и печатает `STALE_DOCS [...]`.
2. Если список пуст — индекс свежий.
3. Если непуст — прочитай ТОЛЬКО перечисленные доки и обнови их `summary`/`keywords`
   в `docs/doc-map.json` (поля `path`/`title`/`codePaths`/`sha` не трогай — это поля генератора).
4. Это разовая сверка свежести: повторно за сессию `yarn doc-map` гонять не нужно, если доки не менялись.

## Перед касанием файла кода — селекция

Код в этом репо живёт в `src/`. Привязка по `codePaths` — **ЖЁСТКАЯ**.
PreToolUse-хук **блокирует** Read/Edit/Write файла кода, пока его привязанные доки не прочитаны
в этой сессии. Это энфорсится харнессом и действует на ЛЮБУЮ ипостась ИИ, включая субагентов —
обойти нельзя.

1. **Путь (первичный ключ) — ОБЯЗАТЕЛЕН, не рекомендация.** Док, привязанный к файлу по
   `codePaths`, читается ДО касания кода, без исключений. Если хук заблокировал операцию —
   не ищи обходных путей (`Bash`/`cat`/`sed` и т.п.), а открой названную доку через `Read`
   и повтори операцию.
2. **Ключевые слова (вторичный ключ) — по суждению.** Для concept-задач (движок экспозиции,
   миграции, PWA, тема и т.п.) найди в `docs/doc-map.json` доки, чьи `keywords`/`summary` совпадают с темой,
   даже без привязки по путям. Здесь гейта нет — решаешь сам.
3. Релевантность вторичных доков оценивай по `summary` — не открывай тело ради проверки.
4. Не перечитывай уже прочитанное — см. «Без повторных проходов» ниже.
5. Нет привязанных доков и тема не совпала — работай без доков (это не ошибка).

> Жёсткой является только путь-привязка (первичный ключ) — она не отключается.
> Сменная (экспериментальная) — лишь стратегия вторичного keyword-отбора (пункт 2);
> данные индекса при её смене не трогаются.

## Без повторных проходов — журнал прочитанного

Держи в уме на протяжении сессии, что уже прочитано — по паре (док, блок/диапазон строк),
а не только по имени файла:

1. Док или блок, прочитанный ранее в этой сессии, повторно НЕ читай — используй то, что уже в контексте.
2. Нужен другой блок того же дока — прочитай только его; прежний блок и остальной файл не перечитывай.
3. Хук может снова предложить уже прочитанные доки — это норма: не открывай заново, сошлись на ранее прочитанное.

> **Повторное ПОЛНОЕ чтение неизменённого файла хук блокирует автоматически** (он уже в контексте).
> Нужен конкретный участок — читай через `Read` с `offset`/`limit`. Изменённый файл перечитать можно.

## Синхронизация индекса — ОБЯЗАННОСТЬ при правке доков

Создал/изменил/удалил `.md` → в ТОМ ЖЕ заходе синхронизируй индекс, это не опционально:

- запусти `yarn doc-map` (обновит `sha`/`codePaths`/`title` и список протухших);
- для протухших доков обнови `summary`/`keywords`;
- (`docs/doc-map.json` коммить вместе с докой — с разрешения пользователя).

Если синхронизацию пропустить, при следующем чтении этой доки по индексу хук покажет
юзеру предупреждение о рассинхроне (`⚠ doc-map: индекс рассинхронизирован…`). Не доводи до этого.
