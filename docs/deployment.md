# Сборка, деплой и эксплуатация

Приложение без бэкенда — это статика, так что весь деплой сводится к выкладке `dist/`.
Интересное начинается на обновлении уже установленного PWA.

| Аспект | Решение |
|---|---|
| Сборка | Vite, vite-plugin-pwa в режиме `generateSW` |
| Хостинг | Ещё не выбран; статика с HTTPS (обязателен для service worker). Base path — через `VITE_BASE` |
| CI | GitHub Actions: typecheck, lint, steiger, vitest, build с двумя base, size-limit, Playwright |
| Кэширование | Precache всего бандла; сетевых запросов в рантайме нет, runtime caching не нужен |
| Обновление | `registerType: 'prompt'`: новая версия ждёт, пока пользователь нажмёт «Обновить» на плашке |
| Версия каталога | Номер в JSON; при росте номера пользовательские камеры перечитывают спеки по `specId` |
| Миграции | Только аддитивные, с логом в консоль (`data-model.md`) |
| Зависимости | Dependabot раз в месяц: minor и patch одной группой, мажоры отдельными PR; плюс GitHub Actions |

## Заблокированные мажоры зависимостей

Dependabot не предлагает мажорные обновления пакетов из списка `ignore` в
`.github/dependabot.yml`: они ломают линтинг или типы. Минорные и патч-версии этих пакетов
приходят как обычно.

| Пакет | Держим | Почему | Когда снимать блок |
|---|---|---|---|
| `typescript` | 6.x | typescript-eslint поддерживает TS < 6.1 | typescript-eslint объявит поддержку TS 7 |
| `eslint`, `@eslint/js` | 9.x | `eslint-plugin-jsx-a11y` и `eslint-plugin-import` поддерживают ESLint ≤ 9 | оба плагина добавят ESLint 10 в peer-зависимости |
| `eslint-plugin-unicorn` | 64.x | с 66-й версии требует ESLint ≥ 10.4 | вместе с переходом на ESLint 10 |
| `@types/node` | 24.x | типы должны совпадать с версией Node из `.nvmrc` | вместе с переходом на новый Node |

Снимать блок — убрать пакет из `ignore` и обновить его вручную вместе со связанными пакетами
одним PR.

## Service worker

Регистрирует его `useRegisterSW` из `virtual:pwa-register/react` в плашке обновления
(`src/widgets/appShell/ui/updateBanner`), с `immediate: true`. Без этого флага регистрация ждёт события `load`,
а оно происходит раньше, чем React монтирует плашку: до первого рендера идёт асинхронная
гидратация из IndexedDB. В итоге service worker не регистрировался бы вовсе.

Precache-манифест собирает `generateSW` по `globPatterns`. `manifest.webmanifest` плагин
добавляет сам, поэтому в шаблон он не входит: дубль с другой ревизией валит Workbox при
инициализации (`add-to-cache-list-conflicting-entries`), install проходит без кэширования,
и приложение молча перестаёт работать офлайн. Именно это ловит офлайн-тест (`testing.md`).

## Манифест и иконки

Манифест собирает vite-plugin-pwa. `scope` и `start_url` выводятся из `VITE_BASE`,
`display: standalone`. Иконки (64, 192, 512, maskable 512, apple-touch 180, favicon)
генерирует `@vite-pwa/assets-generator` из `public/icon.svg` при каждой сборке. Чтобы заменить
иконку, достаточно заменить этот SVG.

## Ловушки

- **Base path.** При деплое в подпапку `base` в Vite, `scope` и `start_url` в манифесте
  и `base` роутера должны совпадать, иначе установленное приложение откроется в браузере,
  а не в своём окне. Все три значения выводятся из `VITE_BASE`; CI собирает вариант
  с подпапкой. Для GitHub Pages сборка кладёт копию `index.html` в `404.html`.
- **Установка на iOS.** Значок на главный экран добавляется только вручную через меню
  «Поделиться», так что в интерфейсе нужна одноразовая подсказка (итерация 1).

## Бюджет размера

`size-limit` в CI проверяет начальный JS и CSS в gzip: не больше 200 КБ. Превышение валит
сборку на пуше, а не обнаруживается на телефоне в парке. Если бюджет не сходится из-за HeroUI,
запасной план — использовать кит только для сложных контролов (select, modal, toast),
а простое верстать на Tailwind.

## Разработка с телефона

`localhost` считается безопасным контекстом, а IP компьютера в локальной сети — нет.
Service worker и установка PWA по `http://192.168…` не работают, поэтому dev-сервер
поднимается по HTTPS с сертификатом mkcert. Пошагово — в `README.md`, раздел
«Проверка на телефоне».
