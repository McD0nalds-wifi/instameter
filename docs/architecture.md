# Архитектура и стек

## Главный принцип

Движок рекомендаций не знает ни про React, ни про IndexedDB. Это чистая функция, которой
передают замер, спеку камеры и плёнку, а обратно получают рекомендацию с предупреждениями.
Благодаря этому его можно покрыть тестами целиком и позже подключить второй источник замера
без правок.

Путь от снимка к совету: файл из `<input type="file" capture>` → exifr читает EXIF → расчёт
EV₁₀₀ → `recommend(measurement, camera, film, options)` → карточка совета. Снимок не
сохраняется: из него читается EXIF, а сам файл отбрасывается. В IndexedDB лежат только список
камер и настройки, поэтому до появления лога кадров объём данных измеряется килобайтами.

## Стек

| Задача | Решение | Почему |
|---|---|---|
| Сборка | Vite 8, `@vitejs/plugin-react` | Как в рабочих проектах |
| Язык | TypeScript 6, `strict` + `noUncheckedIndexedAccess` | В движке много индексации по массивам диафрагм и коррекций |
| UI-кит | HeroUI v3 (React Aria внутри) | Доступность, тач-цели, фокус из коробки |
| Стили | Tailwind v4 | Основа HeroUI v3; правила — `styling.md` |
| Иконки | lucide-react, поштучный импорт | Tree-shaking, около 1 КБ на иконку |
| Состояние | Jotai | Атомарность ложится на цепочку «активная камера → совет» |
| Роутинг | wouter | Около 2 КБ, настоящие URL, кнопка «назад» на Android |
| IndexedDB | `idb` | Около 1 КБ, миграции через `upgrade(db, oldVersion)` |
| Валидация | valibot | Модульный, в разы легче zod |
| EXIF | exifr | Понимает HEIC с iPhone и JPEG с Android |
| PWA | vite-plugin-pwa (`generateSW`), `@vite-pwa/assets-generator` | Precache всего бандла, иконки из одного SVG |

Библиотеки форм и i18n нет: форма одна (FR-05), язык один. Шрифт — системный стек,
внешних шрифтов и CDN нет, потому что сеть в рантайме запрещена.

## Структура: FSD

Слои и импорты сверху вниз: `app → pages → widgets → features → entities → shared`.
Кросс-импортов между слайсами одного слоя нет. Границы проверяет Steiger (`yarn steiger`).

```
src/
  main.tsx              точка входа: гидратация и монтирование
  app/
    entrypoint/         App: Jotai Provider, Router с base, оболочка
    model/              bootstrap (БД и гидратация до первого рендера), применение темы
    routes/             маршруты wouter
    styles/             index.css: Tailwind, HeroUI, системный шрифт, safe-area
  pages/
    measure/            MeasurePage — главный экран: замер и совет
    catalog/            CatalogPage — справочник моделей
    myCameras/          MyCamerasPage — личный список
    settings/           SettingsPage — тема и прочие настройки
  widgets/
    appShell/           оболочка: нижняя навигация, плашки хранилища и обновления
    (позже) шапка с переключателем активной камеры
  features/
    switchTheme/        выбор темы system / light / dark
    measureScene/       замер: снимок с камеры или из галереи → EXIF → Measurement
    (позже) selectCamera, addCustomCamera
  entities/
    preference/         настройки пользователя (тема, поправка устройства): схема, атомы, appSettings
    measurement/        замер сцены: схема, текущий замер в памяти, сводка
    camera/             каталог камер: схема CameraSpec и cameras.json
    film/               каталог плёнок: схема FilmSpec и films.json; @x/camera — для ссылок камер
    (позже) userCamera
  shared/
    api/db/             обёртка над idb: схема, версии, миграции
    config/             strings.ts — строки интерфейса, routes.ts — пути, env.ts — base роутера
    lib/plural/         склонения через Intl.PluralRules
    lib/format/         числа экспозиции по-русски: EV, ступени, диафрагма, выдержка
    lib/exif/           чтение экспопары из EXIF снимка (exifr, сборка lite)
    lib/schema/         общие примитивы valibot: положительные числа, slug, URL
    lib/testing/        setupUser для тестов
    lib/exposure/       ev, recommend — чистые функции без React
```

В слое `app` нет сегментов `ui` и `providers`: Steiger запрещает UI в `app` и требует
называть сегменты по назначению, а не по содержимому. Компоненты оболочки живут в
`widgets/appShell`, пути маршрутов — в `shared/config`, чтобы их видели и `app`, и `widgets`.

Внутри слайса: публичный `index.ts`, сегменты `ui/`, `model/`, `api/`, `lib/`, тесты
в `__tests__/` рядом с модулем. Слайсы называются по сущности в camelCase и в единственном числе внутри слоя (Steiger,
`fsd/inconsistent-naming`), компонент страницы — с суффиксом `Page`.

Правило «движок не знает про React» FSD выполняет само: `shared` ниже всех слоёв
и не может импортировать ни атомы, ни компоненты.

## Состояние и хранилище

**IndexedDB — источник правды, атомы Jotai — её кэш в памяти.**

- `shared/api/db` ничего не знает о сущностях: хранит записи как `unknown` и отвечает только
  за версии схемы и миграции.
- Сущность (`entities/*`) владеет схемой valibot, атомами и функциями чтения и записи.
  Пример — настройки пользователя в `src/entities/preference`.
  Запись идёт через write-атом: сначала в БД, затем в атом. Обратного направления нет.
- Данные из БД при чтении проходят через схему valibot: там окажется мусор после неудачной
  миграции. Битая запись пропускается с `console.warn`, а не роняет приложение.

### Гидратация до первого рендера

`main.tsx` до `createRoot` вызывает `bootstrap` из `src/app/model`: тот открывает БД, читает настройки и камеры и кладёт их в Jotai store
через `store.set`. Первый рендер получает уже готовые данные: ни один компонент не обрабатывает
состояние «ещё не загрузилось», нет Suspense и мигания пустого списка. Данных килобайты, чтение
занимает миллисекунды и укладывается в бюджет холодного старта 2 с.

Если БД не открылась (приватный режим, квота, отказ браузера), приложение стартует с пустыми
данными и показывает плашку о том, что изменения не сохранятся. Признак ошибки — `appDbAtom`
со значением `null`.

## Base path

От хостинга зависят `base` в Vite, `scope` и `start_url` в манифесте и `base` роутера.
Хостинг ещё не выбран, поэтому всё выводится из одной переменной `VITE_BASE`
(по умолчанию `/`):

- `vite.config.ts` передаёт её в `base` и в манифест;
- роутер берёт `import.meta.env.BASE_URL` без завершающего слеша;
- сборка кладёт копию `index.html` в `404.html` — так GitHub Pages отдаёт SPA по любому пути;
  в precache этот файл не попадает.

CI собирает приложение дважды: с корнем и с `VITE_BASE=/instameter/`, чтобы проверить,
что подпапка не сломалась. Рассогласование этих трёх значений — ловушка, при которой
установленное приложение открывается в браузере, а не в своём окне.

## Тема

Пользователь выбирает `system`, `light` или `dark`, значение хранится в `appSettings`.
При `system` тема следует `prefers-color-scheme` и переключается на лету. На улице при ярком
солнце часто нужна светлая тема, даже если телефон в тёмной, — отсюда ручной выбор.
Применение темы описано в `styling.md`.

## Строки интерфейса

Интерфейс только на русском, но все строки лежат в одном модуле `shared/config/strings.ts`,
а не в компонентах. Склонения — через `Intl.PluralRules`, не конкатенацией.
