итерации, но учтено в модели данных сразу, чтобы потом не мигрировать схему.

## Нефункциональные требования

Офлайн и приватность — не пожелания, а следствия сценария: приложение открывают в парке
с плохим интернетом и скармливают ему личные снимки с геометками.

| Категория | Требование |
|---|---|
| Офлайн | После первой загрузки весь функционал доступен без сети, сетевых запросов в рантайме нет вообще |
| Приватность | Снимки не покидают устройство; EXIF читается в браузере, файл не сохраняется до v3 |
| Телеметрия | Отсутствует полностью |
| Производительность | Разбор EXIF и расчёт совета до 300 мс на снимке 12 МП |
| Размер | Начальный бандл до 200 КБ в gzip без учёта шрифтов (контролирует `size-limit` в CI) |
| Браузеры | Safari на iOS 16+, Chrome на Android 10+; десктоп — только для разработки |
| Интерфейс | Цели нажатия от 44 пунктов, контраст для чтения на солнце, тёмная тема |
| Доступность | Ни одно решение не передаётся одним только цветом |
| Сохранность данных | Список камер переживает обновление приложения и смену версии схемы |

На iOS данные сайта могут быть очищены после долгого простоя. Для установленного на главный
экран PWA риск ниже, но не нулевой — отсюда FR-21 про экспорт, который становится обязательным
ровно тогда, когда появляется лог кадров.

### Почему такая разница в цене

Сцен-пикер дёшев потому, что это таблица из восьми строк и список кнопок. Если движок сразу
принимает `Measurement` с полем `source`, то второй источник данных подключается без правок
в алгоритме.

Вспышка — одна формула, но к ней нужен ввод дистанции до объекта и два разных предупреждения —
не добивает и выбивает передний план. Плюс полевая проверка ведущего числа, которая стоит
не часов, а пачки плёнки.

Лог дорог потому, что это не фича, а второй продукт внутри первого: хранение бинарных данных,
сжатие фото перед сохранением, список с пагинацией, форма оценки, статистика и риск потери
данных, из-за которого туда же притягивается экспорт.
